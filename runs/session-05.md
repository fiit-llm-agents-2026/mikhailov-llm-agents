# Сессия 5 — долгосрочная память

**Память:** `SqliteSaver` — история диалога, `SqliteStore` — профиль и факты пользователя; файл `product.db` (`*.db` и `*.db-*` в `.gitignore`)
**Пользователь:** namespace `(user_id, "profile")` и `(user_id, "memories")`; чекпоинт привязан к паре user_id/thread_id
**Профиль:** `name`, `gluten_free`, `lactose_free`, `vegan`; `None` означает «неизвестно»
**Инструменты:** `save_memory(text, kind)` и `search_memories(query)` работают с тем же Store
**Запуск:** `uv run python src/agent.py --user-id <id> --thread-id <id>`
**Модель:** `MODEL_CHEAP` из `.env`, она же обновляет профиль через trustcall

Перед каждым вызовом модели `memory_prompt` читает профиль из Store. После ответа
extractor получает новую реплику пользователя и существующий профиль через `existing`:
новые сведения дополняют документ, а поля, которых реплика не касается, сохраняются.
Обновление выполняется один раз за ход, после печати ответа.
Это последовательный вызов в CLI: ответ уже показан, но следующая реплика
ожидается только после завершения extractor.

В сессии 4 перезапуск продолжал прежний тред. Здесь проверка другая: новый
`thread_id` начинает пустую историю, но агент узнаёт пользователя по `user_id`.

## Первый диалог: знакомство

Процесс 1:

```bash
uv run python src/agent.py --user-id session05-65e6b8b1 --thread-id first
```

Фрагменты фактического диалога; длинные ответы сокращены:

```text
you> Меня зовут Иван. Я не употребляю глютен.
[tool] save_memory({'text': 'Иван не употребляет глютен (gluten-free).', 'kind': 'semantic'})
agent> Запомнил, Иван: вы не употребляете глютен. 🍽️
...
[profile] {'name': 'Иван', 'gluten_free': True, 'lactose_free': None, 'vegan': None}

you> Также я не употребляю лактозу.
[tool] save_memory({'kind': 'semantic', 'text': 'Иван не употребляет лактозу (lactose-free).'})
agent> Запомнил: вы не употребляете также лактозу. ✅
...
[profile] {'name': 'Иван', 'gluten_free': True, 'lactose_free': True, 'vegan': None}

you> Запомни: я предпочитаю гречку.
[tool] save_memory({'kind': 'semantic', 'text': 'Иван предпочитает гречку.'})
agent> Запомнил: вы предпочитаете гречку. 🥣
...
you> exit
```

После сообщения о лактозе имя и ограничение глютена остались в профиле.
Предпочтение гречки хранится отдельным фактом, а не полем `Profile`.

## Новый диалог после перезапуска

Процесс 2, тот же пользователь, **новый thread_id**:

```bash
uv run python src/agent.py --user-id session05-65e6b8b1 --thread-id second
```

```text
you> Как меня зовут и какие у меня ограничения?
agent> Вас зовут Иван. Ваши ограничения по питанию:

- **Без глютена** (gluten-free)
- **Без лактозы** (lactose-free)
- Веганство — не указано (не ограничение)
...
[state] 2 messages, ~78 tokens

you> Найди мои сохранённые предпочтения через search_memories с пустым запросом, затем подбери мне продукты с учётом ограничений.
[tool] food_search({'gluten_free': True, 'lactose_free': True})
[tool] search_memories({'query': ''})
agent> Вот что сохранилось в вашей памяти:

- Иван предпочитает гречку
- Иван не употребляет лактозу (lactose-free)
- Иван не употребляет глютен (gluten-free)
...
[profile] {'name': 'Иван', 'gluten_free': True, 'lactose_free': True, 'vegan': None}
[state] 7 messages, ~616 tokens
```

В новом треде после первого ответа всего два сообщения: вопрос и ответ.
Имя и ограничения пришли из Store, история первого диалога не подгружалась.
Отдельный процесс подтвердил, что память переживает перезапуск.

## Разделение пользователей

Процесс 3: `--user-id session05-65e6b8b1-other --thread-id second`.
Вопрос — об имени, ограничениях и сохранённых предпочтениях.

```text
[tool] search_memories({'query': ''})
agent> По вашим сохранённым данным:

- **Имя:** не указано (в профиле поле `name` пустое, и в памяти ничего не сохранено).
- **Ограничения в питании:** не заданы — безглютеновость, безлактозность и веганство отмечены как неизвестные (`null`).
...
[profile] {'name': None, 'gluten_free': None, 'lactose_free': None, 'vegan': None}
```

Одинаковый thread_id не смешивает пользователей: профиль и факты Ивана
другому user_id не достались.

## Что показал прогон

| Проверка | Наблюдение | Результат |
|---|---|---|
| Дополнение профиля | После сообщения о лактозе сохранились имя и `gluten_free=True` | Старые поля не потерялись |
| Новый диалог | Агент назвал имя и оба ограничения; в истории всего 2 сообщения | Профиль прочитан из Store |
| Перезапуск процесса | Второй диалог запущен отдельной командой | Память сохранилась в SQLite |
| Поиск фактов | `search_memories('')` вернул три сохранённых факта | Предпочтение гречки доступно в новом треде |
| Подбор продуктов | `food_search` получил `gluten_free=True`, `lactose_free=True` | Сохранённые ограничения использованы в вызове инструмента |
| Другой пользователь | Профиль пуст, поиск не вернул фактов при том же `thread_id` | Данные разделены по `user_id` |

Главное отличие от восстановления истории: первый ответ во втором диалоге
получен без сообщений первого диалога. Чтобы узнать имя и ограничения, агенту
не понадобилось искать старый тред или восстанавливать его резюме.

## Два способа записи памяти

| Механизм | Что сохраняет | Когда |
|---|---|---|
| Trustcall | Имя и пищевые ограничения в `Profile` | После каждого ответа |
| `save_memory` | Отдельный факт с видом `semantic`, `episodic` или `procedural` | По решению агента во время диалога |

`search_memories` ищет по словам без учёта регистра; пустой запрос перечисляет факты.
Это лексический поиск, без embeddings. Одинаковый текст не дублируется,
перефразированные факты автоматически не объединяются.

В прогоне сохранена **семантическая память**: имя, ограничения и предпочтение
гречки. Инструмент также принимает `episodic` для событий и `procedural` для
постоянных инструкций, но эти два вида отдельными диалогами не проверялись.
Поле `kind` — метка документа; отдельного механизма исполнения сохранённых
инструкций нет.

[Описание архитектуры памяти](../docs/architecture.md).

## Проверки и ограничения

Локальный тест `tests/test_memory.py` проверяет сохранение факта, отсутствие
дубликата при повторной записи, поиск без учёта регистра, пустую выдачу для
другого пользователя и чтение после повторного открытия SQLite.

Команда проверки из корня репозитория:

```bash
PYTHONPATH=src uv run python -m unittest discover -s tests -p 'test_memory.py'
```

При подготовке отчёта тест повторно запущен через `.venv/bin/python`:
`Ran 1 test`, `OK`.

Все три сохранённых запуска CLI завершились с кодом `0`. В stderr есть
предупреждения сериализации Pydantic для `UserContext`; в этих запусках они
не помешали чтению и записи памяти.

Проверка подтверждает перенос памяти и передачу фильтров в `food_search`.
Качество всех рекомендаций отдельно не оценивалось: в сохранённом ответе
модель оспорила статус пармезана из выдачи, не вызвав `food_check`.
